n = 10이면 비교는 모두 몇 번일까

(n−1) + (n−2) + … + 1
= n(n−1) / 2i번째 바퀴(i = 0부터)는 n−1−i번 비교
n = 1045번 n = 1,000499,500번 n × 2비교 횟수는 약 4배, Θ(n²)

어떤 바퀴에서 교환이 한 번도 없으면 이미 정렬된 상태입니다. 거기서 멈추면 이미 정렬된 입력은 Θ(n)으로 끝나요.

버블 정렬은 Θ(n²): n이 두 배가 되면 비교는 약 네 배가 됩니다.

코드로 옮길 때 정할 세 가지

  1. 1
    바깥 반복: 몇 바퀴?한 바퀴에 하나씩 맨 뒤가 확정됩니다. n개면 n−1바퀴로 충분해요. 마지막 한 칸은 저절로 제자리입니다.
  2. 2
    안쪽 반복: j는 어디까지?a[j]와 a[j+1]을 비교합니다. i바퀴째에는 뒤쪽 i칸이 이미 확정이니, a[j+1]이 확정 구역과 배열 끝을 넘지 않게 범위를 정하세요.
  3. 3
    비교와 교환오름차순이라면 왼쪽이 더 클 때만 두 값을 바꿉니다.

두 값 바꾸기 (임시 변수 사용)

int t = x;   /* x를 잠시 보관 */
x = y;
y = t;

임시 변수 없이 x = y; y = x; 라고 쓰면 두 값이 같아져요.

바깥 반복은 바퀴, 안쪽 반복은 옆 칸 비교입니다.

최소 힙의 규칙은 하나: 부모 ≤ 자식

  • 모양
    위에서부터, 왼쪽부터 빈칸 없이 채운 이진 트리
  • 규칙
    모든 노드에서 부모 ≤ 자식
  • 형제끼리는 상관없음
    9와 6, 8과 4처럼 순서가 없어도 됩니다
  • 그래서
    가장 작은 값은 항상 루트에 있습니다

최솟값은 항상 맨 위에 있습니다. 정렬된 배열과는 다릅니다.

트리를 배열에 담기

노드나 배열 칸을 누르면 부모와 자식 위치가 표시됩니다.

정수 나눗셈  5 / 2 = 2, 4 / 2 = 2. 그래서 왼쪽, 오른쪽 자식 모두 i / 2로 부모를 찾을 수 있어요.

1번 칸부터 쓰는 이유  공식이 간단해져요. 0번부터 쓰면 부모는 (i − 1) / 2, 자식은 2i + 1과 2i + 2입니다.

부모는 i / 2, 자식은 2i와 2i + 1. 포인터 없이 배열 하나로 충분합니다.

삽입: 맨 끝에 넣고, 부모보다 작으면 위로

멈추는 때
부모보다 작지 않을 때(≥), 또는 루트(i = 1)에 도착했을 때

올라가는 횟수는 많아야 트리 높이만큼, O(log n)입니다.

4와 바꾸면?
4가 2의 부모가 되어 규칙이 깨집니다. 그래서 더 작은 자식과 바꿉니다.

내려갈 때는 항상 두 자식 중 더 작은 쪽과 교환합니다.
