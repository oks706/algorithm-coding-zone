## 버블 정렬

**아이디어.** 옆에 있는 두 칸을 비교해서 순서가 틀리면 바꿉니다. 왼쪽 끝에서 오른쪽 끝까지 한 번 훑는 것을 '한 바퀴'라고 하면, 한 바퀴가 끝날 때마다 남은 값 중 가장 큰 값이 맨 뒤로 떠오릅니다. 거품이 수면으로 올라오는 모습과 닮아서 버블 정렬이라고 부릅니다.

**예.** `[24, 9, 31, 15, 40, 6, 18]`의 첫 바퀴

| 비교 | 결과 | 배열 |
|---|---|---|
| 24, 9 | 교환 | `[9, 24, 31, 15, 40, 6, 18]` |
| 24, 31 | 그대로 | |
| 31, 15 | 교환 | `[9, 24, 15, 31, 40, 6, 18]` |
| 31, 40 | 그대로 | |
| 40, 6 | 교환 | `[9, 24, 15, 31, 6, 40, 18]` |
| 40, 18 | 교환 | `[9, 24, 15, 31, 6, 18, 40]` |

비교 6번 만에 가장 큰 40이 맨 끝에 자리를 잡았습니다.

**순서.**

1. n개를 정렬할 때는 n − 1바퀴면 충분합니다. 마지막 한 칸은 저절로 제자리에 놓입니다.
2. i번째 바퀴(0부터 셈)에서는 뒤쪽 i칸이 이미 확정이므로, 앞쪽 n − 1 − i쌍만 비교합니다.
3. 오름차순이면 왼쪽 값이 더 클 때만 바꿉니다.

**비교 횟수.** (n − 1) + (n − 2) + … + 1 = n(n − 1) / 2번입니다. n = 10이면 45번, n = 1,000이면 499,500번입니다. 그래서 시간은 Θ(n²)이고, n이 두 배가 되면 비교는 약 네 배가 됩니다.

**조기 종료.** 어떤 바퀴에서 교환이 한 번도 없으면 이미 정렬된 상태입니다. 거기서 멈추면 이미 정렬된 입력은 Θ(n)에 끝납니다.

**성질.** 같은 값은 바꾸지 않으므로 같은 값끼리의 순서가 유지됩니다(안정 정렬). 추가 메모리도 거의 필요 없습니다.

**자주 하는 실수.**

| 증상 | 확인할 곳 |
|---|---|
| 원래 없던 값이 섞이거나 가장 큰 값이 사라짐 | 비교가 배열 끝을 넘어가지 않는지 (`a[j+1]`의 범위) |
| 같은 값이 여러 번 나옴 | 임시 변수 없이 `x = y; y = x;`로 바꾸지 않았는지 |
| 가장 큰 값만 맨 뒤로 가고 나머지는 그대로 | 바퀴를 여러 번 도는지 |
| 큰 수부터 나옴 | 비교 부등호 방향 |

## 선형 탐색과 이진 탐색

**선형 탐색.** 처음부터 하나씩 비교하며 찾습니다. 정렬되어 있지 않아도 쓸 수 있습니다. 최악의 경우 n번 비교하므로 O(n)입니다. 찾는 값이 앞쪽에 있으면 금방 끝납니다.

**이진 탐색.** 정렬된 배열에서만 쓸 수 있습니다. 가운데 값과 비교해서, 찾는 값이 더 작으면 왼쪽 절반, 더 크면 오른쪽 절반에서 다시 찾습니다. 한 번 비교할 때마다 후보가 절반으로 줄어서 많아야 약 log₂n + 1번이면 끝나고, 시간은 O(log n)입니다. n이 100만이어도 20번 정도면 충분합니다.

**예.** `[4, 8, 15, 16, 23, 42, 50, 61]`에서 42 찾기

- 선형 탐색: 4, 8, 15, 16, 23, 42 순서로 6번 비교
- 이진 탐색: 가운데 16과 비교해 오른쪽 절반으로, 다음 가운데 42에서 찾음. 2번 비교

**정렬에 드는 비용.** 정렬에는 O(n log n)이 들지만, 한 번 정렬해 두면 그 뒤로는 찾을 때마다 O(log n)입니다. 같은 데이터에서 여러 번 찾을수록 이득입니다.

**같은 값이 여러 개일 때.** 선형 탐색은 처음 나온 위치를 찾고, 이진 탐색은 그중 아무 위치에서나 멈출 수 있습니다. 둘 다 틀린 답이 아닙니다.

**구현할 때 주의할 점.** 이진 탐색은 후보가 한 칸만 남았을 때도 확인해야 하고, 매번 범위가 실제로 줄어들어야 합니다. 범위가 줄지 않으면 끝나지 않습니다.

## 최소 힙

**정의.** 두 가지 조건을 만족하는 이진 트리입니다.

1. **모양:** 위에서부터, 왼쪽부터 빈칸 없이 채운 완전 이진 트리
2. **순서:** 모든 노드에서 부모 ≤ 자식

그래서 가장 작은 값은 항상 루트에 있습니다. 형제끼리는 순서가 없어서, 정렬된 배열과는 다릅니다.

**배열로 저장하기.** 완전 이진 트리라서 포인터 없이 배열에 차례로 담을 수 있습니다.

| 칸 번호를 1부터 쓸 때 | 칸 번호를 0부터 쓸 때 |
|---|---|
| 부모 `i / 2`, 자식 `2i`, `2i + 1` | 부모 `(i − 1) / 2`, 자식 `2i + 1`, `2i + 2` |

(나눗셈은 정수 나눗셈. 예: 5 / 2 = 2)

**넣기 (heapify-up).** 새 값을 맨 끝에 넣고, 부모보다 작으면 부모와 바꾸며 위로 올라갑니다. 부모보다 작지 않거나 루트에 닿으면 멈춥니다.

- 예: 힙 `[2, 5, 3, 9, 6]`에 1을 넣으면 `[1, 5, 2, 9, 6, 3]`

**최솟값 꺼내기 (heapify-down).** 루트(최솟값)를 꺼내고, 맨 끝 값을 루트로 옮긴 뒤 아래로 내려 보냅니다. 두 자식 중 **더 작은 쪽**과 바꾸고, 자식이 없거나 더 작은 자식보다 작거나 같으면 멈춥니다. 더 큰 자식과 바꾸면 그 자식이 다른 자식의 부모가 되어 규칙이 깨집니다.

- 예: 힙 `[1, 4, 2, 7, 5, 3, 6]`에서 꺼내면 `[2, 4, 3, 7, 5, 6]`

**시간.** 트리의 높이가 약 log₂n이고 넣기와 꺼내기는 한 경로만 따라가므로 모두 O(log n)입니다.

| 연산 | 시간 |
|---|---|
| 최솟값 보기 | O(1) |
| 넣기 | O(log n) |
| 최솟값 꺼내기 | O(log n) |
| n개를 넣고 모두 꺼내기 (힙 정렬) | O(n log n) |

**어디에 쓰나.** 우선순위 큐, 힙 정렬, Dijkstra 최단 경로, Prim 최소 신장 트리, Huffman 코드처럼 '지금 가장 작은 것'을 반복해서 꺼내야 하는 곳에 씁니다.

## 고쳐서 다시 만들기

`src/`에 글꼴을 넣기 전의 원본 HTML이 있습니다. 원본을 고친 다음 아래처럼 글꼴을 넣어 완성본을 만듭니다. 원본의 `/*@FONTS@*/` 자리에 문서에 쓰인 글자만 골라낸 글꼴이 들어갑니다.

```bash
pip install fonttools brotli
npm pack @ibm/plex-sans-kr@1.1.0 @ibm/plex-mono@2.5.0
mkdir -p fonts/kr fonts/mono
tar -xzf ibm-plex-sans-kr-1.1.0.tgz -C fonts/kr
tar -xzf ibm-plex-mono-2.5.0.tgz -C fonts/mono

python3 tools/build_deck.py src/bubble-sort-heap.src.html bubble-sort-heap.html \
  fonts/kr/package/fonts/complete/woff2/hinted fonts/mono/package/fonts/complete/woff2
```

오류 확인(선택, [Playwright](https://playwright.dev/) 필요):

```bash
node tools/check.js bubble-sort-heap.html
```
